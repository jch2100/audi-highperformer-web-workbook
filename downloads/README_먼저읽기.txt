내 고객관리 — 먼저 읽기
======================

이 파일은 수업용 고객관리 공간의 사용 안내입니다. 본인이 만든 고객관리 상위 폴더에 고객_프로파일_양식.txt와 함께 넣습니다. 공통 실습은 가상 고객으로 진행합니다. 실제 고객정보는 회사에서 허용한 정보·계정·공유 범위에서만 사용합니다.

1. 폴더 역할
01_Raw: 채팅·음성 받아쓰기 메모 또는 직접 올린 원본 TXT를 보관합니다. 원문과 기존 파일명은 임의로 고치지 않습니다.
02_Customer_Profile: 고객코드별 TXT 한 개를 유지합니다. 상단은 확인된 최신 상황, 하단은 출처가 있는 누적 원문 기록입니다.
03_Customer_Asset_DB: 제공된 Customer_Asset_DB.xlsx의 고객목록 시트입니다. 고객코드당 한 행으로 전체 목록과 다음 행동을 봅니다. 자세한 원문은 고객 프로파일에서 확인합니다.

2. 처음 한 번 설정
① 내 ChatGPT 프로젝트와 Google Drive 고객관리 상위 폴더·01·02·03을 만듭니다.
② 상위 폴더에 이 README와 고객_프로파일_양식.txt를 직접 업로드합니다. 양식은 빈 참고 파일이며 고객 기록이 아닙니다.
③ 03_Customer_Asset_DB에 제공된 Customer_Asset_DB.xlsx를 하나만 올리고 직접 엽니다. 고객목록 시트의 4행은 제목, 5행부터는 빈 고객 입력 공간입니다.
④ 프로젝트 소스에 본인의 고객관리 상위 폴더를 연결합니다. 강사의 시연 폴더를 연결하지 않습니다.
⑤ 웹교재의 ‘3·소스와 지침’에서 제공하는 지침을 프로젝트 설정에 저장합니다. 본인의 실제 상위 폴더명을 사용합니다.
⑥ 작업할 Work 채팅에서 Google Drive를 선택하고 연결 계정과 실제 파일 읽기를 확인합니다. 읽기 성공만으로 저장까지 된 것은 아닙니다.

3. 새 상담 메모를 남길 때
프로젝트의 Work 채팅에서 고객코드와 상담 내용을 적거나 음성으로 받아씁니다. 고객코드가 없거나 같은 고객인지 모호하면 먼저 확인합니다.
예: ‘C001 고객의 후속 상담 메모야. 접촉일은 …이고, 나눈 내용은 …야.’
01에 입력 원문을 저장하고, 02의 해당 고객 기록과 03의 같은 고객 한 행에 반영하도록 요청합니다. 음성 입력은 받아쓰기된 텍스트를 기준으로 합니다.

4. 기존 TXT를 처리할 때
기존 고객 메모 TXT를 01_Raw에 직접 올린 뒤, 파일명을 지정해 처리 요청을 보냅니다. 업로드만으로 자동 처리되지 않습니다.
예: ‘01_Raw의 [실제 파일명]을 직접 읽고, 고객코드와 근거를 확인한 뒤 02·03에 반영해줘. 모호한 내용은 먼저 물어봐.’
01의 원본과 파일명은 보존합니다. 같은 원문의 중복 반영을 피하고, 여러 고객이 담긴 파일은 고객별 해당 원문만 나눕니다.

5. 저장 결과 확인
01: 입력한 원문 또는 올린 원본 파일이 그대로 있습니다.
02: 해당 고객의 하단에 출처 Raw 파일명과 원문이 있고, 이전 기록도 남아 있습니다. 상단은 확인된 최신 상황입니다.
03: 같은 고객코드의 행이 하나 있고, 프로파일 파일명·마지막 반영 Raw 파일명이 맞습니다.
AI의 ‘완료’ 답변만 믿지 말고 실제 파일을 직접 엽니다. 일부만 저장되면 미완료 단계와 재시도할 내용을 확인합니다.

6. 기록 원칙
확인되지 않은 이름·차량·날짜·상담 단계는 추측하지 않습니다. 알려지지 않은 정보는 미정, 의미가 모호하거나 서로 충돌하면 확인 필요로 둡니다.
접촉일과 기록 생성일·파일 처리일을 구분합니다. 해석이 불분명한 숫자 날짜나 ‘다음 주’는 먼저 확인합니다.
새 정보가 명시적으로 바꾸지 않는 한 기존 확인 정보를 보존합니다. 늦게 처리한 과거 메모로 최신 상황을 과거로 되돌리지 않습니다.
같은 고객은 같은 고객코드를 사용하며, 이름만 같다고 합치지 않습니다.
이 안내는 프로젝트 지침을 대신하지 않습니다. 차이가 있으면 임의로 처리하지 말고 확인합니다. 연락 문구는 초안으로만 만들고 발송·공유 설정 변경은 별도로 결정합니다.
